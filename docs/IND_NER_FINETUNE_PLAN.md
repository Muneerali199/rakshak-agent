# RAKSHAK — Indic NER Fine-Tune Handoff (Option B)

> **Audience:** another developer. This document is self-contained: what to build,
> which data already exists (locally + on Hugging Face), how to train on the Omen
> (WSL2 + RTX 5050 8GB), how to evaluate honestly, and how to wire it in without
> breaking the deterministic serving path.

---

## 1. Goal

Train a token-classification model that labels FIR narrative text into the exact
entity kinds the RAKSHAK graph already expects:

**PERSON | PHONE | ACCOUNT | VEHICLE | IPC | LOCATION | ORGANIZATION**

It is a *peer* to the existing regex extractor — never a replacement — and only
**proposes** spans. No LLM, no generative output, no auto-write to the case graph.

Why this one:
- Closes the documented gap in `backend/api/ingest.py:46-47` (regex refuses to
  guess Devanagari names: *"must not guess"*).
- Trains in < 1h on an RTX 5050 8GB; serves on a gaming GPU in milliseconds.
- Output shape = regex output shape = `ExtractedEntity` (`ingest.py:95`), so the
  pipeline after extraction is unchanged.
- Cannot hallucinate entities not written in the text (span tagger, not generator).

## 3. What the model is

- Base: `distilbert-base-multilingual-cased` (safe default, warm HF cache) or
  `ai4bharat/indic-bert` (preferred for Hindi recall when it installs offline).
- Task: `AutoModelForTokenClassification`, BIO tag scheme.
- Tags (freeze before training — changing mid-run invalidates results):

```
O  B-PERSON I-PERSON B-PHONE I-PHONE B-ACCOUNT I-ACCOUNT
B-VEHICLE I-VEHICLE B-IPC I-IPC B-LOCATION I-LOCATION
B-ORGANIZATION I-ORGANIZATION
```

- Mapping: BIO spans → `ExtractedEntity(kind, surface, normalized, span)`, exactly
  matching `backend/api/ingest.py:95`, so `merge_into_graph` accepts it unchanged.

## 4. Dataset build (BIO labelling) — the most bug-prone step

`backend/scripts/build_indner_data.py`:

1. Load `mentions.jsonl` + `fir.jsonl` (from `backend/output/` or the HF repo).
2. Align every mention surface to token positions in the narrative. **Write a
   verifier that re-renders spans from labels and asserts string equality with
   the source surface** — an off-by-one here is a silent training bug.
3. Augment to ≥ 8k rows with template variants over the *structured* blocks
   (same ground truth, re-worded), to teach robustness beyond literal bench text.
4. Adversarial rows that MUST be present:
   - pure Devanagari, no honorifics (`"रमेश कुमार ने ..."`)
   - code-mix (`"Ramesh Kumar ne Sunita Devi ko ..."`, `"Ravi ने AC... खाते में"`)
   - name-order swaps (`"Prasad Ram"` vs `"Ram Prasad"`)
   - spaced/dotted identifiers (`"KA 05 MJ 4890"`, `"AC 00 76 61 77 11"`)
   - no-entity narratives → all `O`
   - false-positive guards: Hindi verbs that look like names, "Section" in prose,
     place names inside narrative (label LOCATION)
5. Split: ~90/10, hold-out 500 rows stratified by district and field.
6. Save as HF-ready JSONL + dataset card (mirror `docs/huggingface/DATASETS.md`).

## 5. Training (Omen / WSL2, RTX 5050 8GB)

```bash
# on Omen WSL2 (Ubuntu 22.04), CUDA 12.x, python 3.11 venv
pip install torch transformers datasets seqeval peft accelerate
python scripts/train_indner.py \
  --base distilbert-base-multilingual-cased \
  --data hf/rakshak-fir-synth \
  --out out/rakshak-indner-distilbert \
  --lr 5e-5 --epochs 3 --seq 256 --batch 16 --fp16
```

- Plain fp16/bf16 — **do NOT** use bitsandbytes 4-bit for a 110M BERT-class model.
- Metrics per epoch: token-accuracy, **span-F1 (seqeval)**, and specifically
  **PERSON-F1** (the kind regex fails today).
- Expected wall time 30–60 min on the 5050. If > 2h, rows or seq-length are wrong.
- Deliverable: HF `out/rakshak-indner-distilbert/` + `model_card.md`.

## 6. Evaluation (the slide that protects you)

`backend/scripts/eval_indner.py` — run on the 500 hold-out rows:

| kind | regex-F1 | indner-F1 | hybrid-F1 |
| --- | --- | --- | --- |

- `hybrid` = union of regex + model spans; regex wins label ties (deterministic).
- **Acceptance bar (honest):** hybrid PERSON-F1 on code-mix ≫ regex; hybrid never
  worse than regex on PHONE/ACCOUNT/VEHICLE. If a kind regresses, fall back to
  regex for that kind — a documented policy, not a defeat.
- This exact table goes on the PPT slide ("regex baseline vs trained Indic NER vs
  hybrid" — numbers reproducible via `python scripts/eval_indner.py`).

## 7. Serving integration (Mac keeps serving; Omen optional)

- `backend/api/ingest.py`: pluggable extractor registry
  `engine: regex | indner | hybrid` (default `hybrid`; auto-fall back to `regex`
  when model files are absent — **ingest must never 500 on a missing model**).
- New route: `POST /api/ingest/extract?engine=...` →
  `{entities, regex_entities, model_entities, agreement:[], disagreements:[]}`.
- Model load lazy + cached; `backend/api/extract/indner.py` = loader + BIO→ExtractedEntity.
- `/api/security/posture` gains an `extractors` block (honest labels: `regex=builtin`,
  `indner=distilbert-<date>`, `engine active: ...`).
- Every extractor output stays **proposals**: nothing reaches the graph without the
  existing officer review path.

## 11. Honest labels (judges will probe these)

- Never say "the AI reads the FIR and decides". Say: *two extractors propose spans,
  a deterministic policy merges them, an officer approves.*
- Never claim live IndicXlit / Bhashini / DigiLocker — sims are labeled `sim`;
  production adapters are documented, not running.
- Eval numbers come from this run's hold-out; reproducible via `eval_indner.py`.
- `engine_name()` (transliteration) still returns `builtin-rule-romanizer` on this
  box — keep that truth intact.

## 12. Risk register

| Risk | Mitigation |
| --- | --- |
| `ai4bharat/indic-bert` won't install offline | use `distilbert-base-multilingual-cased` (warm HF cache on Mac) |
| Token drift vs regex tokenization | BIO aligner + render-check verifier at dataset-build time |
| PERSON-F1 not better than regex | hybrid still helps on code-mix; if not, ship regex-only and say so |
| WSL/CUDA driver issues on Omen | 110M model trains on CPU too; Mac fallback possible |
| Venue has no internet | all artifacts vendored (HF package + model weights copied before travel) |
| HF push blocked / creds invalid | dataset is already local + packaged; push is a bonus, not a dependency |
